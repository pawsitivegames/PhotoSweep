# SAFE-01 keeper selection and proposal model

`KeeperSelection.tla` models completed-result keeper choices, cleanup inclusion, review state, and the boundary between proposing media for Trash and dispatching provider Trash. It has three groups: two eligible groups and one locked group. The first eligible group has three media keys so manual multi-keep choices are representable; the second has two disjoint keys; the locked group is a singleton with a third disjoint key set. `InvGroupsHaveDisjointMembers` checks that a media key cannot be a keeper in one modeled set and a Trash target in another. The fixed `EligibleGroups` constant abstracts all completed groups allowed into cleanup, including groups hidden by the active review filter. Existing entitlement and media safety gates determine eligibility before this model's scope.

The model includes all six strategies. Their finite scores abstract each evidence field and fallback chain; tied scores use stable media-key ordering (`asset-a < asset-b < asset-c`). Automatic groups have one deterministic keeper. Manual keeper choices may retain multiple items, and manual Trash-all has no keeper before an explicit strategy choice.

`trashTargets` is an explicit per-group set. The invariant `InvProposedTrashTargetsAreExact` requires it to equal `GroupMembers[group] \ keepers[group]` for every included group and the empty set for every excluded group. Additional invariants require keepers and Trash targets to be disjoint, locked groups to remain excluded, and every included non-keeper to be proposed.

Bulk Auto Keep can select any of the six strategies. It includes every eligible group, replaces manual keeper and Trash-all decisions with one deterministic strategy keeper per group, clears manual provenance, and recomputes the proposed targets. It leaves reviewed status unchanged only when the inclusion and keeper/target plan remain the same. It clears prior review for changed or newly included plans, never adds reviewed IDs, and does not dispatch Trash. `SelectGroup` models the separate explicit `select_groups` checkbox action: it re-includes that one group and records the user's per-set review. `SkipGroup`, `ReviewGroup`, manual keeper choice, and manual Trash-all are also per-set review actions. `ConfirmTrash` is the only dispatch transition; it is enabled only after every eligible group has been reviewed and a proposal exists, and it snapshots the reviewed set.

The regular configuration explores states reachable from `Init`. The closure configuration starts from every finite state satisfying `InvSelectionSafety`, then applies the same unrestricted `Next` relation. This checks invariant preservation and the bulk action properties over all well-formed safe states, without imposing an action schedule. Both configurations cover bulk strategy, manual keeper, manual Trash-all, skip, explicit select/re-include, review, and confirmation actions. The negative control sets `UnsafeAutoTrash = TRUE`; the runner passes it only when TLC reports `InvBulkStrategyDoesNotDispatchTrash` violated on a `BulkApplyStrategy` transition.

This finite abstraction is scoped to the completed-results proposal transition. It does not model default recomputation, legacy migration, persisted-strategy hydration, or prove that the TypeScript implementation refines the model; SAFE-01's default/migration/hydration behavior remains covered by keeper decision and provider review storage properties plus the isolated app integration tests. It also does not execute provider adapters, media-level favorite or repeated-identity checks, review-only or access-limit gates, asynchronous authorization writes, or browser commands. The scores are finite examples, not a claim that provider evidence is complete or that a user-facing quality fallback has been selected.

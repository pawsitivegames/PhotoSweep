# SAFE-01 keeper selection and proposal model

`KeeperSelection.tla` models completed-result keeper choices, cleanup inclusion, review state, and the boundary between proposing media for Trash and dispatching provider Trash. It has three groups: two eligible groups and one locked group. The first eligible group has three media keys so manual multi-keep choices are representable; the second has two disjoint keys; the locked group is a singleton with a third disjoint key set. `InvGroupsHaveDisjointMembers` checks that a media key cannot be a keeper in one modeled set and a Trash target in another. The fixed `EligibleGroups` constant abstracts all completed groups allowed into cleanup, including groups hidden by the active review filter. Existing entitlement and media safety gates determine eligibility before this model's scope.

The model includes all six strategies. Their finite scores abstract each evidence field and fallback chain; tied scores use stable media-key ordering (`asset-a < asset-b < asset-c`). The static `MissingMembers` constant marks group keys without a usable current record. It abstracts an absent mapping, a non-object value, a record whose `mediaKey` differs from its map key, or a blank `dedupKey`. Complete automatic groups have one deterministic keeper; incomplete automatic groups keep all usable current members. Manual and valid legacy keeper choices contain only usable members, and manual Trash-all has no keeper before an explicit strategy choice.

`trashTargets` is an explicit per-group set. The invariant `InvProposedTrashTargetsAreExact` requires it to equal the usable members minus keepers for each included complete group, and the empty set for excluded or incomplete groups. `InvKeeperKeysPresent` and `InvIncompleteGroupProposesNoTrash` check the partial-hydration fail-closed rule. Additional invariants require keepers and Trash targets to be disjoint, locked groups to remain excluded, and every included non-keeper in a complete group to be proposed.

The registered config fixes `MissingMembers = {asset-a}`, so group 1 is incomplete; this profile uses an absent `asset-a`, the highest-scored Best Quality member, while the abstraction also covers unusable records. Groups 2 and 3 are complete. The model does not quantify over every possible missing/unusable-member subset or execute the TypeScript `mediaItems` mapping. SAFE-01 implementation tests cover absent members and truthy corrupt records through `DuplicateReviewSession` and its Trash plan.

Before groups enter session keeper, selection, or Trash state, the implementation requires a nonblank unique string group ID, finite similarity in the inclusive range 0–1, and a dense array of at least two unique nonblank string member keys, with every index present as an own array property. Empty and singleton groups, sparse or otherwise malformed member-key arrays, invalid similarity values, and every group sharing a colliding ID are excluded. The model assumes this validated group structure and similarity range and does not model malformed group objects or arbitrary container corruption.

Bulk Auto Keep can select any of the six strategies. It includes every eligible group, replaces manual keeper, Trash-all, and stale-key fallback decisions with `StrategyKeepers`: one strategy keeper for complete groups and all usable current members for incomplete groups. It clears manual provenance and recomputes the proposed targets. It leaves reviewed status unchanged only when the inclusion and keeper/target plan remain the same. It clears prior review for changed or newly included plans, never adds reviewed IDs, and does not dispatch Trash. `RestoreValidLegacyChoice` abstracts any nonempty saved legacy keeper subset whose keys still exist, including a valid keep-all choice; passive default recomputation (`PassiveDefaultRecompute`) recalculates it using the current strategy. `RestoreStaleKeeperFallback` abstracts saved keeper data with no usable current identities, including all-stale and malformed identity arrays, manual, stale, or legacy-preserved provenance without a validated per-group override, and a present malformed override root paired with persisted selected/reviewed groups. It conservatively keeps every usable current member under distinct `stale-fallback` provenance. A genuinely absent legacy root without provenance remains on the automatic default path. Passive recomputation preserves the fallback and proposes no Trash. The properties also require passive recomputation to preserve manual keepers and Trash-all, while an explicit bulk strategy action can replace the stale fallback. `SelectGroup` models the separate explicit `select_groups` checkbox action: it re-includes that one group and records the user's per-set review. `SkipGroup`, `ReviewGroup`, manual keeper choice, and manual Trash-all are also per-set review actions. `ConfirmTrash` is the only dispatch transition; it is enabled only after every eligible group has been reviewed and a proposal exists, and it snapshots the reviewed set.

The fast configuration starts at `Init` and exhaustively explores the complete reachable graph for the declared finite constants. TLC checks all configured safety invariants, including exact proposed Trash targets, keeper exclusion, zero Trash targets for the stale-data fallback, review-before-confirmation, and no dispatch from bulk strategy, plus the configured action properties for explicit selection, passive recomputation, and fallback replacement. The negative control sets `UnsafeAutoTrash = TRUE`; it passes only when TLC finds `InvBulkStrategyDoesNotDispatchTrash` violated by `BulkApplyStrategy`.

`KeeperSelection.closure.cfg` is a separate exploratory query that asks TLC to enumerate every valuation satisfying `InvSelectionSafety` as an initial state. That arbitrary-state initialization is impractical for the fast gate and is not part of the current SAFE-01 evidence. The fast claim is limited to states reachable from `Init`; it does not claim preservation from every possible safe valuation.

The model includes finite abstract transitions for a valid legacy choice, a stale or malformed-data fallback, passive default recomputation, and explicit strategy replacement. It does not execute the TypeScript storage decoder or prove that the implementation refines these transitions; implementation behavior remains covered by stored-review-scope and keeper-decision tests plus app integration tests. A valid intentional empty keeper array remains a separate Trash-all choice only when its manual provenance is valid. The model also does not execute provider adapters, media-level favorite or repeated-identity checks, review-only or access-limit gates, asynchronous authorization writes, or browser commands. The scores are finite examples, not a claim that provider evidence is complete or that a user-facing quality fallback has been selected.
